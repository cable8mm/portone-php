# IDEAS.md — 포트원 server SDK PHP 버전

**한 줄 요약**: 포트원 공식 server-sdk 레포에 PHP만 없어서, wifinote.net 결제 도입을 위해 직접 PHP 버전을 만든다.

**결정 준비도**: 판단 가능 — 필요(본인 서비스 결제), 기존 대안, 한국 조건, 수익 구조, 갱신 방식이 답변됨. 외부 수요와 공식이 PHP를 안 만든 이유는 본인이 중요하지 않다고 함.

## 1. 발단

- 포트원 공식 레포(https://github.com/portone-io/server-sdk)에 PHP만 없음.
- wifinote.net에 결제를 넣어야 함.

## 2. 문제와 대상 사용자

- 문제: PHP로 포트원 서버 API를 쓸 SDK가 없음.
- 대상: 본인. wifinote.net 결제 때문에 SDK가 필요함.

## 3. 아이디어

- 포트원 server SDK의 PHP 버전을 만든다.
- 포트원 문서를 따라 SDK를 갱신한다.
- SDK 자체는 수익이 없음. 이득은 본인 서비스에 결제를 도입하는 것.

## 4. 기존 대안

- 비공식 PHP 패키지가 있었으나 deprecated됨.
- 나머지 패키지도 대부분 오래되어 관리되지 않음.

## 5. 증거

- 존재 증거
  - 공식 레포에 PHP 외 언어 SDK는 있음 (사용자 발언 "php 만 없네").
  - 비공식 PHP 패키지는 있었으나 deprecated, 대부분 미관리.
- 수요 증거
  - 본인이 불편함. wifinote.net에 결제를 넣어야 함.
  - 본인 외 수요는 확인 안 됨. 본인은 관심 없다고 함.
- 반증
  - 없음.

## 6. 반론과 의문

- 본인 외 다른 사용자의 수요 → 중요하지 않고 관심 없음 (기각)
- 공식이 PHP를 지원하지 않는 이유 → 관심 없음 (기각)

## 7. 한국 조건

- 포트원은 한국 주력 PG의 래퍼 성격이라, 포트원을 지원하면 대부분의 PG사별 패키지를 따로 만들지 않아도 됨.

## 8. 검증 결과

- 검증 미실시.

## 9. 논의 중 바뀐 점 / 기각된 방향

- 외부 사용자 수요 확인, 공식이 PHP를 안 만든 이유 파악은 하지 않기로 함.
- 본인이 필요로 하는 것이라 성공/실패 개념이 의미 없고, 아무도 안 써도 된다고 함.
